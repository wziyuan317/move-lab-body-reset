# MOVE LAB 身体定位首页重构设计

## 目标

把现有身体定位首页重构为清晰、可操作的 3 步流程：用户先选择不适区域，再描述主观感受，最后获得安全边界内的办公室动作建议。页面继续保留穿运动服的 3D 游戏人物作为视觉中心，但默认不再展示脱离身体轮廓的肌肉网格。

视觉以用户提供的 MOVE LAB 深蓝游戏化参考图为唯一目标：左侧任务流程、中央人物、右侧结果、底部身体区域入口。原有 15 个动作教程、搜索、动作过程图、到位图和运动康复说明全部保留。

## 已确认的问题

1. `symptomIds` 只改变按钮状态，没有进入推荐计算或结果文案，导致“描述感受”没有可见结果。
2. 当前肌肉模式隐藏全部无关结构，再把可见肌肉重新归一化到固定高度，用户失去完整人体轮廓和空间参照。
3. 选择身体区域后立即切到肌肉模式，破坏中央人物持续承担定位参照的目标。
4. 当前相机没有使用 `regionCameraPresets.zoom`，人物模式的观察轴和目标点也不一致，造成放大后偏移、裁切和透视异常。
5. 当前页面的 Hero 和白色 3D 工具卡改变了参考图的核心布局层级。

## 推荐架构

采用三层定位结构：

1. **大区域定位**：中央着装 3D 人物和底部区域卡共同选择颈部、肩部、胸背、腰背、髋臀、大腿、膝部和小腿／踝部。
2. **具体位置定位**：右侧展示始终带完整身体轮廓的正面／背面身体分区图。用户可以点选肌群，支持左右侧和多选。
3. **复杂关节定位**：膝、肩胛和踝进入局部图，优先使用普通用户能理解的位置名称，再在第二层解释可能相关肌群。

Z-Anatomy 继续保留为折叠的“专业解剖模式”，用于补充教育说明，不参与默认定位流程。

## 首屏布局

### 顶部导航

- 左侧为 MOVE LAB 标识和“身体放松图鉴”副标题。
- 中部保留“身体定位”“动作库”“知识库”入口；本次只让现有可用入口真正可点击，不新增无实现页面。
- 右侧保留教程入口；搜索继续在动作库中使用。

### 左侧任务栏

- 顶部“今日任务：定位不适”。
- 三张明确可交互的步骤卡：选择位置、描述感受、获得建议。
- 当前步骤高亮，完成步骤显示勾选和已选摘要。
- 用户点击已完成步骤可以返回修改。
- 未完成位置时，感受选项不可用；未完成位置和感受时，不生成最终教程匹配。

### 中央人物

- 默认展示穿白色运动上衣、深蓝运动短裤和运动鞋的男性游戏角色。
- 人物保持完整可见并位于彩色圆形平台中心。
- 大区域热点依附人物，标签使用普通部位名称。
- 选择部位后相机平滑放大，但人物轮廓仍然保留。
- 正面／背面切换只改变观察方向，不改变选择。
- 默认不允许无限自由旋转；限制为前后与小范围观察，避免用户迷失方向。

### 右侧结果栏

- 未选择时显示简短操作提示。
- 选中大区域后显示“当前位置”和具体位置图。
- 完成感受选择后显示安全判断、相关区域解释和匹配教程。
- 出现红旗选项时隐藏训练 CTA，改为暂停训练与专业评估提示。
- 专业肌肉名称属于解释层，不作为第一步必答项。

### 底部区域卡

- 使用深红、黄色、蓝色、绿色、紫色、橙色和青色的宝可梦式区域卡。
- 每张卡包含部位插图、部位名称和一个常见描述。
- 当前选择使用白色外框、勾选状态和轻微抬升反馈。

## 3 步交互流程

### 第 1 步：选择位置

用户可从人物热点或底部区域卡进入。选择后：

- 中央人物平滑聚焦对应区域，但保持身体上下文。
- 右侧打开正面／背面身体分区图或复杂关节局部图。
- 左侧第 1 步变为完成，第 2 步变为当前。
- 切换大区域时清除不属于新区域的具体位置选择，保留安全选项。

### 第 2 步：描述感受

感受支持多选：酸紧／发僵、活动受限、感觉无力、肿胀、刺痛／麻木。

- 每次选择立即更新左侧摘要和右侧说明。
- `symptomIds` 进入结果模型，用于调整教育文案、安全提示和动作强度建议。
- 感受标签不用于推断疾病，也不直接对应某一受损组织。
- “肿胀”“刺痛／麻木”“感觉无力”必须触发更谨慎的提示；若同时勾选进展性症状等红旗，则阻断训练推荐。

### 第 3 步：获得建议

只有完成位置和至少一个感受后才显示最终匹配：

- 显示用户已选的区域、侧别、具体位置和感受。
- 推荐 1–3 个现有教程，并说明匹配依据。
- 提供停止条件和非诊断边界。
- 主 CTA 为“匹配教程”，进入动作库后保留当前定位状态，返回时恢复。

## 身体分区图

### 普通身体图

默认采用 `react-muscle-highlighter` 提供的完整正面／背面人物图，保留未选区域的浅色人体轮廓。选中区域使用统一语义色，而非每块肌肉随机颜色：

- 默认轮廓：暖灰蓝。
- 可点击区域：浅蓝灰。
- Hover：黄色。
- 已选：珊瑚红。
- 多选附加：蓝色描边和编号，不再为每块肌肉分配不同饱和色。

该组件只负责它原生支持的宽泛区域，例如斜方肌、肩部、胸部、腰背、臀部、股四头肌、腿后侧、小腿、胫骨前肌、膝和踝。

### 复杂关节图

膝部至少提供：

- 正前方／髌骨周围；
- 内侧；
- 外侧；
- 后方；
- 大腿前侧；
- 大腿后侧；
- 小腿上端；
- 无法确定。

肩胛至少提供肩前、肩外侧、肩后、肩胛骨内侧、肩胛骨下方和无法确定。踝部至少提供踝前、内踝、外踝、跟腱、小腿后侧和无法确定。

局部图使用真实插图资产，不使用漂浮肌肉网格、CSS 图形或文本代替图像。

## 3D 人物与相机

### 角色资产

优先评估 Quaternius Ultimate Modular Men Pack 中的着装角色；若人物比例不适合参考图，再评估 Universal Base Characters 与兼容运动服组合。

下载时保存包内许可证和下载日期。只有包内明确标记 CC0 的版本才允许把原始 GLB 纳入公开仓库；若下载版本采用 QAL，则只在合规的产品构建中使用，不把原始资产作为可独立下载的资产分发。

### 相机规则

- 角色加载后计算完整包围盒和包围球。
- 默认镜头根据可视区域尺寸自动计算距离，人物脚底与平台中心对齐。
- 区域聚焦使用“人物整体中心 + 区域目标偏移 + 固定安全边距”，不再把区域坐标直接当作不一致的相机轴。
- 相机始终看向当前区域目标；正背面只反转观察方向。
- 滚轮缩放限制在安全范围，并围绕当前目标缩放。
- 重置、切换区域、窗口尺寸变化后重新执行 `fitCameraToTarget`。
- 采用缓动过渡，尊重 `prefers-reduced-motion`。

## 数据流

探索状态继续由 URL 持久化：

```text
regionId
targetIds
targetSides
symptomIds
redFlagIds
viewSide
step
```

推荐结果分三种：

- `idle`：没有选择区域；
- `incomplete`：已选区域，但没有选择感受；
- `ready`：位置与感受完成，可以推荐教程；
- `caution`：存在需要谨慎处理的感受，但没有红旗；
- `blocked`：存在红旗，不推荐训练。

推荐排序仍以现有区域和具体位置映射为基础。感受只调整强度、提示和说明，不用于诊断或声称某动作可以治疗疾病。

## 组件调整

- `HomePage`：改为参考图的单屏游戏化布局。
- `AssessmentPanel`：步骤卡变为真实流程控制器，展示完成摘要。
- `BodyExplorer`：只管理着装人物、大区域热点和相机；不再自动进入肌肉模式。
- `BodyScene`：统一相机坐标、自动构图和区域聚焦。
- 新增 `BodyRegionMap`：封装完整正背面身体图、左右侧多选和颜色语义。
- 新增 `JointRegionMap`：展示膝、肩胛和踝的局部位置图。
- `RecommendationPanel`：增加 `incomplete` 和 `caution` 状态，并等待感受完成后再展示教程。
- `bodyMap`：增加普通分区 slug、侧别、关节位置和感受策略映射。

## 响应式规则

- 桌面宽屏：左／中／右三列，底部区域卡横向排列，首屏高度约为一个视口。
- 中等宽度：中央人物优先，左侧步骤和右侧结果保持双栏或上下紧邻，不把关键结果推到长页面底部。
- 手机：人物、区域卡、具体位置、感受、结果按步骤分页或手风琴展开；底部固定显示当前步骤和下一步 CTA。
- 所有交互目标至少 44 × 44 px，保证键盘焦点、ARIA 标签和可见选中状态。

## 验收标准

1. 点击“定位身体信号”的任一步骤都有可见状态变化和明确下一步。
2. 未选择感受时不显示最终教程推荐；选择感受后结果文案和状态发生变化。
3. 默认流程不出现脱离人体的漂浮肌肉网格。
4. 每个具体位置都能在完整人体图或局部关节图中看到准确位置。
5. 膝部支持正前、内、外、后及无法确定，并支持多选。
6. 3D 人物在默认、区域聚焦、缩放、正背面和窗口变化后均保持视觉居中，不被异常裁切。
7. 1440 × 900 桌面状态在结构、层级、色彩和主要比例上匹配参考图。
8. 390 × 844 手机状态无横向溢出，核心 3 步可完整完成。
9. 红旗状态不显示训练 CTA；原有 15 个教程和搜索功能不减少。
10. 自动测试、Sites 构建和 GitHub Pages 构建通过，浏览器主流程和控制台检查通过。

## 明确不做

- 不根据主观位置诊断疾病或推断受损组织。
- 不在本轮新增账户、计划记录、云同步和后端服务。
- 不删除 Z-Anatomy 资产，只将其移出默认定位流程。
- 不修改原有教程动作内容，除非发现与新定位数据的明确映射错误。
