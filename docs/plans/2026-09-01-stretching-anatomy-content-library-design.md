# 《拉伸解剖学》中文动作内容库设计

- 日期：2026-09-01
- 状态：待用户审阅
- 来源：用户提供的《Stretching Anatomy》第三版 PDF
- 来源规模：265 个 PDF 页面，初步识别约 83 个独立动作
- 目标：生成可独立交给其他 AI 使用的中文内容包，不直接改动当前网站

## 1. 交付目标

从来源 PDF 中逐页整理全部动作、术语、身体区域、目标肌肉、训练计划引用和页码关系，形成一个可追溯、可校验、可直接映射到 MOVE LAB 网站与 3D 人体模型的中文内容库。

内容包必须满足以下使用场景：

1. 另一位 AI 可以从清单入口读取全部动作，并将动作导入当前网站。
2. 用户点击 3D 人体的大区域或具体肌肉后，可以通过稳定结构 ID 找到对应动作。
3. 用户打开动作详情时，可以加载结构化中文内容及起始、过程、到位图片。
4. 每条内容都能追溯到 PDF 页码、书内页码和章节。
5. 人工可以通过 Markdown 文件逐动作审阅，程序可以通过 JSON 文件稳定读取。

## 2. 已确认原则

- 最终内容包中的标题、说明、术语、字段和值全部使用简体中文。
- 不保存或分发原书页面扫描图，不直接复制原书插图。
- 动作说明使用忠实转述与结构化整理，不大段照录英文原文。
- 原书未明确提供的呼吸、剂量、常见错误、简化版本、停止条件和不适用人群，需要标记为“规范化补充”或“安全补充”，不能冒充原书结论。
- 静态拉伸动作制作 2 张图：起始状态、到位状态。
- 动态拉伸动作制作 3 张图：起始状态、运动过程、到位状态。
- 动作图统一使用无脸中性运动人物、简洁运动服和纯净背景。
- 图片中不放动作名称、步骤或长文字；只保留红色目标肌肉、蓝色动作方向和黄色稳定提示。
- 图片为原创动作引导图，书中插图只用于理解姿势，不作为复制或风格临摹对象。
- 当前内容包不直接修改网站代码；另一位 AI 依据导入说明与索引完成填充。

## 4. 稳定 ID 规则

稳定 ID 不依赖页面标题、文件名或展示顺序，避免名称调整后索引失效。

- 动作：`动作-区域-三位序号`，例如 `动作-足小腿-001`。
- 身体区域：`区域-名称`，例如 `区域-髋臀`。
- 肌肉：`肌肉-规范中文名`，例如 `肌肉-臀大肌`。
- 关节附近结构：`结构-规范中文名`，例如 `结构-膝前区`。
- 来源页面：`页面-PDF三位页码`，例如 `页面-PDF-019`。

三维模型自身的网格或节点名称只作为外部绑定值保存在 `三维模型绑定.json`，不参与动作和肌肉的稳定 ID。模型重新导出后，只更新绑定文件，不改动动作数据。

## 5. 动作数据契约

每个动作的 `内容.json` 至少包含：

```json
{

  "中文动作名称": "初级坐姿脚趾伸肌拉伸",

  "动作类型": "静态拉伸",
  "难度等级": "初级",
  "适用部位": ["足背", "踝前侧"],
  "主要目标肌肉ID": ["肌肉-趾长伸肌"],
  "次要目标肌肉ID": ["肌肉-胫骨前肌"],
  "起始姿势": "",
  "动作步骤": [],
  "呼吸引导": "",
  "拉伸强度": "",
  "持续时间与次数": "",
  "常见错误": [],
  "简化版本": "",
  "停止条件": [],
  "不适用人群": [],
  "动作要点": [],
  "左右侧规则": "双侧分别完成",
  "所需器材": [],
  "信息依据": {
    "原书提取字段": [],
    "规范化补充字段": [],
    "安全补充字段": []
  },
  "图片": {
    "起始": "图片/起始.png",
    "到位": "图片/到位.png"
  },
  "来源": {
    "PDF页码": [],

    "身体区域ID": [],
    "肌肉ID": [],
    "相关动作ID": [],
    "网站路径": ""
  }

```

### 5.1 字段来源规则

- `原书提取字段`：原书明确出现的姿势、步骤、目标肌肉、难度提示和安全注意。
- `规范化补充字段`：为了统一网站体验而补充的呼吸、节奏、动作命名、左右侧规则、常见错误和简化版本。
- `安全补充字段`：停止条件、不适用人群和风险提示。内容采用保守表达，并进入人工复核清单。
- 不允许把推断内容写成作者原意；每个补充字段必须能在 `信息依据` 中识别。

### 5.2 剂量规则

原书明确给出持续时间或次数时，优先忠实转述。原书没有明确剂量时，统一使用保守起点，并标记为规范化补充。剂量不能写成医疗处方，也不能承诺治疗效果。

## 6. 中文术语体系

`标准术语.json` 只保留中文规范词、中文别名和稳定 ID，不在交付内容中暴露英文原词。翻译过程中使用的原文对照仅作为临时工作资料，不进入最终内容包。

每个术语包含：

- 术语 ID。
- 规范中文名。
- 中文常用别名。
- 类型：肌肉、动作方向、解剖方位、关节、身体区域或训练概念。
- 上位结构 ID。
- 左右侧适用规则。
- 使用说明。

规范示例：

- `肌肉-腘绳肌群` → 腘绳肌群。
- `肌肉-臀大肌` → 臀大肌。
- `肌肉-髋屈肌群` → 髋屈肌群。
- `动作方向-外旋` → 外旋。
- `训练概念-关节活动度` → 关节活动度。

同一肌肉不得因章节、左右侧或不同译法生成多个 ID。左右侧通过动作实例字段表达，不复制术语记录。

## 7. 页面级来源追溯

PDF 页码和书内印刷页码分别保存，不用推算值互相替代。

`页面总索引.json` 中每个 PDF 页面包含：

- 页面 ID。
- PDF 页码。
- 书内页码；无印刷页码时为空。
- 章节。
- 页面类型：封面、目录、理论、动作图、动作步骤、训练计划、索引或其他。
- 中文页面摘要。
- 出现的动作 ID。
- 出现的肌肉 ID。
- 引用的其他动作 ID。
- 对应页面摘要文件路径。

每个 PDF 页面都生成一份中文摘要。动作跨页时，标题图页、步骤页和说明页都关联到同一个动作 ID。训练计划章节不重复创建动作，只引用前文已有动作 ID。

## 8. 三维模型与点击映射

### 8.1 肌肉结构记录

`肌肉结构.json` 为每块肌肉或肌群记录：

- 稳定肌肉 ID。
- 规范中文名。
- 所属身体区域 ID。
- 前侧、后侧、内侧或外侧位置。
- 左右侧规则。
- 关联动作 ID。
- 主要目标或次要目标关系。
- 固定界面色标。

### 8.2 模型绑定记录

`三维模型绑定.json` 负责把稳定肌肉 ID 绑定到用户模型：

```json
{
  "肌肉ID": "肌肉-臀大肌",
  "模型网格名称": [],
  "模型节点名称": [],
  "材质名称": [],
  "左右侧": "分别绑定",
  "绑定状态": "等待模型清单",
  "关联动作ID": []
}
```

在未取得模型网格或节点名称清单前，仍然完整生成稳定肌肉 ID、位置、颜色和动作映射；`绑定状态` 标记为 `等待模型清单`。取得模型清单后，只补充绑定值。

### 8.3 点击链路

```text
3D 网格或文字按钮
  → 稳定肌肉 ID
  → 肌肉到动作索引
  → 动作 ID
  → 动作内容与图片路径
  → 网站详情路径
```

身体大区域点击使用 `身体区域到动作.json`；具体肌肉点击使用 `肌肉到动作.json`。多选肌肉时，优先展示同时覆盖更多已选肌肉的动作，再展示单一相关动作。

## 9. 网站路径协议

`网站路径.json` 为每个动作生成：

- 动作 ID。
- 默认详情路径：`/动作教程?动作=<动作ID>`。
- 身体区域筛选参数。
- 肌肉筛选参数。
- 默认图片帧。
- 返回身体定位页时需要保留的选择状态。

另一位 AI 可以根据当前网站最终路由实现调整实际路径，但不得更改动作 ID、肌肉 ID 或索引文件之间的关系。

## 10. 图片生产规范

### 10.1 画面标准

- 用途：网站动作教程与身体定位推荐卡。
- 风格：统一的科学教育运动插画，不写实、不幼稚化。
- 人物：无脸、中性成人体型、固定身体比例和统一运动服。
- 背景：纯白或极浅中性色，不出现教室、健身房、杂物或无关人物。
- 目标肌肉：红色半透明解剖高亮，位置与动作目标肌肉一致。
- 动作方向：蓝色单向或弧形箭头。
- 稳定提示：黄色小箭头或稳定点。
- 禁止：文字、编号、徽标、水印、品牌标志、书中版式和书中插画风格复制。
- 椅子、墙面、毛巾等器材只在动作需要时出现，方向和结构必须正确。

### 10.2 帧标准

- 静态拉伸：起始、到位。
- 动态拉伸：起始、过程、到位。
- 同一动作不同帧保持人物、服装、视角、器材和画幅一致，只改变动作阶段。
- 到位帧体现安全终点，不追求极限活动范围。
- 每张图的 `图像语义.json` 记录帧角色、目标肌肉 ID、动作方向、稳定部位和关键姿势标准。

### 10.3 先行样张

正式批量生成前，先选择 5 个代表动作：

1. 坐姿足部拉伸。
2. 站姿小腿拉伸。
3. 坐姿腘绳肌拉伸。
4. 肩背或胸部拉伸。
5. 一个动态拉伸动作。

样张覆盖坐姿、站姿、器材、上肢、下肢和动态过程。用户确认后再沿用同一规范生成全部图片。

## 11. 提取与生产流程

1. 建立 PDF 页面清单，识别章节、书内页码和页面类型。
2. 提取全部动作标题、动作跨页范围、步骤、目标肌肉和拉伸说明。
3. 建立全局中文术语表，合并同义译名和左右侧重复项。
4. 为每个动作分配稳定 ID，生成结构化字段与 Markdown 审阅页。
5. 从原书说明中分离原书信息、规范化补充和安全补充。
6. 生成身体区域、肌肉、动作和来源页面之间的双向索引。
7. 生成 5 个代表动作样张并完成姿势和风格复核。
8. 批量生成其余动作图片，每个动作逐帧检查。
9. 运行数据模式、文件存在性、ID 唯一性、双向索引和图片完整性验证。
10. 输出验证报告和待人工复核清单。

## 12. 异常与不确定信息处理

- PDF 文字提取错位时，渲染对应页面并以视觉页面为准。
- 动作标题、页码或肌肉列表跨页时，记录全部相关页面，不只记录步骤页。
- 无法确认的肌肉译名进入 `待人工复核.json`，不自行创造新解剖名称。
- 原书动作姿势与现代安全建议存在明显冲突时，保留原书动作事实，在安全补充中明确风险，不悄悄改写来源。
- 无法安全生成的动作图不使用近似图替代；记录失败原因并重新生成。
- 图片中的肌肉位置与结构化肌肉 ID 不一致时，图片不能通过验证。
- 没有模型清单时不猜测网格名称，绑定状态保持为等待。

## 13. 验证规则

### 13.1 数据完整性

- PDF 265 页全部进入页面总索引。
- 每个识别出的动作都有唯一动作 ID、JSON、Markdown 和来源页码。
- 每个肌肉 ID 在术语表和肌肉结构表中唯一。
- 每个动作至少关联 1 个身体区域和 1 个目标肌肉或解剖结构。
- 训练计划引用的动作全部能解析到已有动作 ID。

### 13.2 双向索引

- `肌肉到动作` 与 `动作到肌肉` 必须互相一致。
- `身体区域到动作` 中的动作必须真实存在。
- 相关推荐不得包含自身、失效 ID 或循环错误。
- 网站路径中的动作 ID 必须能定位到内容文件夹。

### 13.3 图片完整性

- 静态动作必须有 2 张不同图片。
- 动态动作必须有 3 张不同图片。
- 图片可以正常解码，尺寸与格式一致。
- 人物、服装、画幅和器材在同一动作各帧中保持一致。
- 目标肌肉、箭头方向和稳定点与 `图像语义.json` 一致。
- 不出现文字、水印、额外人物、错误椅子方向或明显肢体异常。

### 13.4 内容安全

- 所有动作包含停止条件。
- 高风险姿势或症状限制进入人工复核清单。
- 不出现诊断、治愈承诺或替代专业评估的表述。
- 安全补充与原书提取内容可以明确区分。

## 14. 验收标准

- 交付一个独立、可复制的 `stretching-anatomy-cn` 文件夹。
- 全部动作完成中文结构化整理，最终数量与逐页识别结果一致。
- 265 个 PDF 页面均有中文摘要、页码和内容索引。
- 所有静态和动态动作具备规定帧数的原创引导图。
- 术语、身体区域、肌肉和动作之间使用稳定 ID 双向关联。
- 另一位 AI 只读取 `内容包清单.json` 和 `导入说明.md` 即可定位全部数据与图片。
- 取得 3D 模型网格清单后，只需更新 `三维模型绑定.json` 即可完成具体肌肉点击映射。
- 验证报告不存在失效路径、重复 ID、缺图、孤立动作或索引不对称。
- 所有需专业判断或模型信息的项目进入明确的待人工复核清单，不隐藏不确定性。

## 15. 本阶段边界

本阶段负责来源提取、中文内容整理、图片生产和索引内容包，不负责：

- 修改当前网站界面或路由实现。
- 修改或重新导出用户的 3D 模型。
- 猜测尚未提供的 3D 网格、节点或材质名称。
- 进行医疗诊断、个体化康复处方或替代专业审核。
