# 中文动作内容包导入说明

本说明用于将《拉伸解剖》中文动作内容包导入网站或其他结构化系统。导入时必须保留现有稳定 ID、来源页码和人工复核状态。

## 读取顺序

1. 先读取 `内容包清单.json`，确认版本、数量、入口文件与每个文件的 `SHA-256`。清单明确排除自身和 `验证/验证报告.json`：清单不能计算自身；验证报告需要反向校验清单，排除报告可以避免循环失效。
2. 读取 `数据规范/` 下的三份数据模式，先理解动作、肌肉和索引的必填字段、类型、枚举、稳定 ID 与数组去重规则。
3. 读取 `解剖结构/身体区域.json`、`解剖结构/肌肉结构.json` 和 `解剖结构/三维模型绑定.json`，建立稳定结构 ID，再接入人体定位功能。
4. 读取 `动作/动作总索引.json`。这是读取 83 个动作的唯一主入口；先用它取得动作名称、难度、肌肉、页面、内容文件、图片帧和网站路径，不要逐目录猜测动作。
5. 按用途读取 `索引关系/`：大区域入口用 `身体区域到动作.json`，具体肌肉入口用 `肌肉到动作.json`，动作详情回查用 `动作到肌肉.json`，推荐卡片用 `动作相关推荐.json`，路由和返回状态用 `网站路径.json`。
6. 需要来源追溯时，读取 `来源追溯/页面总索引.json` 及其指向的中文页面摘要。
7. 最后按动作总索引定位每个动作内容和图片；结构化导入读取 `内容.json` 和 `图像语义.json`，人工审阅读取 `内容.md`，展示端读取已声明的图片帧。
8. 读取 `验证/验证报告.json` 和 `验证/待人工复核.json`，将警告项保留在待复核状态。

## 联结链路

内容包的主联结是：`动作↔肌肉↔身体区域↔页面↔网站路径`。

- 身体大区域点击：身体区域 ID → 身体区域到动作 → 动作 ID → 动作总索引。
- 具体肌肉点击：肌肉 ID → 肌肉到动作 → 动作 ID → 内容文件与网站路径。
- 动作详情回查：动作 ID → 动作到肌肉 → 肌肉和身体区域的选中状态。
- 来源追溯：动作总索引中的页面 ID → 页面总索引 → 中文页面摘要。
- 网站路径：使用 `/动作教程?动作=<动作ID>`；返回身体定位页时，恢复选中区域、肌肉、动作和图片帧。静态动作与动态动作都以“起始”帧为默认帧。

## 三维绑定边界

`三维模型绑定.json` 当前只提供稳定肌肉 ID 和关联动作。其绑定状态是“等待模型清单”。在取得真实模型清单前，不得猜测模型网格、节点或材质名称，也不得用动作名称反推模型内部名称。取得清单后，只补充该绑定文件，不改动作、肌肉和身体区域 ID。

## 图片状态

当前已存在图片为 176 张，预期图片为 176 张，其中 73 个静态动作每个 2 帧，10 个动态动作每个 3 帧。图片状态为“已完成并通过验证”。静态动作提供起始、到位两帧；动态动作提供起始、过程、到位三帧。每个动作目录的 `图像语义.json` 记录目标肌肉、方向文字、稳定点、姿势标准和最终生成提示词。

## 待人工复核项

对 `验证/待人工复核.json` 中的三维模型绑定与医学专业复核条目逐条处理：

1. 保留复核项的稳定引用和原因，不得为了通过校验而删除。
2. 在专业人员或真实模型清单确认前，不得将待复核项改为已确认。
3. 复核结果应新建版本或使用审核流程写入，不覆盖已有人工审阅稿。

## 禁止项

- 不得导入英文临时源、中间提取文件或书页扫描图。
- 不得更改稳定 ID 或自行合并肌肉记录。
- 不得把规范化补充或安全补充写成原书结论。
- 不得在图片文件尚未存在时伪造成功路径或用近似图替代。
